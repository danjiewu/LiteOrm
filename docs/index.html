Features

为什么选择 LiteOrm

兼顾微型 ORM 的执行效率和完整 ORM 的易用性——不隐藏 SQL，也不强迫你手写 SQL。

极速性能

性能接近原生 Dapper，远超 EF Core。批量插入、更新、关联查询全面领先，内存分配最小。

三种查询方式

Lambda、Expr、ExprString 自由混用：强类型过滤、动态条件拼装、DAO 层手写 SQL 片段各得其所。

自动关联查询

通过 [ForeignType] / [TableJoin] 特性声明关联，无需手写 JOIN，ExistsRelated 一键按关联表过滤。

声明式事务

[Transaction] 特性实现 AOP 事务管理，支持嵌套与回滚，业务代码零侵入。

11 种数据库方言

SQL Server、MySQL、Oracle、PostgreSQL、SQLite，内置达梦、金仓、GaussDB、OceanBase、TiDB、GreatDB 国产数据库支持。

分表与读写分离

IArged 接口支持分表路由，多数据源与只读副本开箱即用，中大型系统的常规需求全覆盖。

Query

同一查询，三种写法

三种方式最终都生成参数化 SQL。Lambda 最直观，Expr 适合动态拼装，ExprString 留给需要精确控制 SQL 的 DAO 层。

// 像写 C# 一样写查询，强类型、可读性最好
var users = await userService.SearchAsync(
    u => u.Age >= 18 && u.UserName!.StartsWith("A"));

// 排序 + 分页
var page = await userService.SearchAsync(
    q => q.Where(u => u.Age >= 18)
          .OrderByDescending(u => u.CreateTime)
          .Skip(20).Take(10));
// 动态拼装条件，适合查询构造器与后台筛选
using static LiteOrm.Common.Expr;

var expr = (Prop("Age") >= 18)
          & Prop("UserName").StartsWith("A");
var users = await userService.SearchAsync(expr);

// 条件可序列化为 JSON，跨层传递、前端直传
string json = expr.ToJson();
// 插值字符串手写 SQL 片段，仅 DAO 层使用
using static LiteOrm.Common.Expr;

int minAge = 18;
var users = await userViewDAO.Search(
    $"WHERE {Prop("Age")} > {minAge}")
    .ToListAsync();

// 插值项自动参数化，既灵活又安全

Service 层提供 Lambda / Expr 入口与 SearchAs 投影查询；DAO 层额外开放 ExprString、DataTable 查询等底层能力。详见查询总览。
